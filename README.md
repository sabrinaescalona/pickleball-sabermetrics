# RallyIQ — video analysis MVP

A mobile-friendly pickleball analytics frontend plus a **local Python video-analysis server**.

## Quick start

Requires Python 3.10+ and a working OpenCV installation.

```bash
cd rallyiq
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn backend.server:app --host 127.0.0.1 --port 8000
```

Open **http://localhost:8000** (not the HTML file directly). Select Film Room, choose a match video, then click **Analyze video automatically**. When processing finishes, jump to detected candidate intervals, mark them confirmed or rejected, and export the results as JSON.

## What is actually automated

- Video upload and asynchronous server-side processing
- Video metadata extraction
- Frame sampling and motion activity analysis in a central court region
- Heuristic segmentation into **candidate active-play intervals**
- Timeline review, confirm/reject, and JSON export

**Important:** This is a motion-based baseline, **not** a YOLO/TrackNet ball tracker. Camera shake, spectators, moving shadows, and cuts can cause false positives; stationary rallies can be missed. It does **not** infer points, players, shot types, winners, 3D trajectories, exact bounce positions, speed, or sabermetrics. Existing dashboard metrics are illustrative/manual and are **not** generated by the video pipeline.

## Privacy and deployment

Uploads remain on the machine running the server under `analysis_data/`. Do not expose this development server to the internet: it has no authentication, quotas per user, rate limiting, or secure video lifecycle management. Uploaded files can be up to 1 GB. `analysis_data/` is excluded from the distributed ZIP.

## Sabermetrics Lab (new)

Open **Sabermetrics** in the left navigation. Import rally-level CSV records with columns `player,partner,opponent,won,match_id`, load fictional demo data, or add a sample row. The backend endpoint `POST /api/sabermetrics` computes an **unadjusted rally wins-above-replacement equivalent** (`rWAR-eq`):

`(rallies won - replacement_rate × rallies observed) / rally_points_per_win_equivalent`

Defaults are **40% replacement rally-win rate** and **11 rally points per win-equivalent**, both adjustable *assumptions*. This is **not validated individual WAR**, not opponent/partner-adjusted, and not derived from the video detector. One rally may be attributed to multiple players, so teammate values must not be summed. The returned 95% Wilson interval covers raw rally win rate under an independence assumption, not rWAR-eq. For meaningful sabermetrics, collect verified point outcomes, serve/receive status, player identity, opponents, partners, and score; fit and calibrate rally expectancy and adjusted player-impact models before labeling anything true WAR.

## Partnership sabermetrics

The Sabermetrics tab now includes **Calculate partnership metrics**, powered by `POST /api/partnerships`. It groups unordered teammate pairs and reports observed rally win rate, unadjusted rallies above a replacement baseline, and assumed win equivalents. If both teammates have outcomes with other partners, it also reports an **unadjusted chemistry gap** versus the mean of their other-partner win rates. This is *not* a causal chemistry estimate or adjusted plus-minus. The CSV import currently uses one row per player-rally and lacks a rally identifier; avoid duplicate rows for the same team rally. The backend supports an optional `rally_id` field to deduplicate records sharing both `match_id` and `rally_id`. For defensible individual and pair impact models, collect distinct rally IDs, both opponents, serve/receive, scoring rules, and multiple partner combinations.

## Adjusted plus-minus (new)

In **Sabermetrics**, use **Adjusted Plus-Minus** to import a separate rally-level CSV with `match_id,rally_id,player,partner,opponent,opponent2,won,serve_team`. Each row represents a **unique rally**, not one row per player. `won` means team A (`player` and `partner`) won. `serve_team` is `A` or `B`. Minimum 20 unique rallies, five players, and some partner rotation. Use **Load fictional APM demo** to exercise the workflow.

`POST /api/adjusted-plus-minus` fits a ridge-regularized logistic model using player coefficients (+1/-1 by team), partnership interaction coefficients, and serving-team advantage. Separate regularization for player and pair terms (default 25 and 80) limits unstable estimates. Outputs include adjusted individual effects, pair synergy effects, and approximate penalized-Hessian intervals. Effects are reported as the percentage-point change from a hypothetical 50% rally probability when applying that coefficient alone, **not** literal observed percentage-point improvements. The model is exploratory, not a validated causal or WAR metric. Identifiability depends on substantial overlap in partner/opponent networks. The APM CSV is intentionally separate from the legacy five-column WAR import, which lacks the required opposing players and rally identifiers.

### Partnership PWAR (experimental)

The **Partnership PWAR** panel uses the same APM rally CSV, skill ratings, and rally-scoring target as the individual PWAR panel. The default **Skill-adjusted** view requires both partners to share a 0.5-point rating band containing at least three players; switch to **Universal** for a shared within-sample baseline.

`POST /api/partnership-pwar` accepts the same JSON payload as `/api/pwar` (`rallies`, `ratings`, `target`). It returns partnership PWAR, PWAR per 100 matches, and model-estimated Chemistry Wins Added. Partnership PWAR compares a real pair to *two* replacement players, with zero assumed replacement synergy; it must not be added to individual PWAR. Results are unvalidated, sensitive to sparse partnership rotations and the provisional within-sample replacement baseline, and are not video-derived.

## Video-to-sabermetrics bridge (new)

In **Film Room**, analyze a fixed-camera video. The detector proposes active-play intervals. Review each interval, enter four distinct player names, mark the winner (Team A or B) and serving team, and click **Send verified rallies to APM / PWAR**. The backend `POST /api/video-rally-records` validates the labels against the saved video job and returns one record per confirmed, fully labeled rally. Records are added to the in-browser APM dataset and can be exported as CSV. Enter skill ratings in Sabermetrics before calculating PWAR.

**Important limitation:** Rally intervals are generated automatically, but point winners, serving teams and player identities are NOT automatically recognized. The bridge intentionally excludes incomplete and rejected rallies rather than inventing results. The current APM needs at least 20 verified rallies, at least five players and partner rotation; a single four-person match is not enough. A future fully automatic version requires trained ball/player tracking, point-end classification, score/serve state recognition and validation against human-labeled video. This is a human-in-the-loop integration, not fully automated sabermetrics.
